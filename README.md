# Shreenivas Joshi — personal site

Next.js (App Router) + TypeScript + Tailwind CSS v4. Every route is statically
prerendered, so it deploys to Vercel as static output with no server work.

```
src/
  app/
    layout.tsx            fonts, metadata, pre-paint theme script
    page.tsx              composes the sections, JSON-LD
    globals.css           design tokens for light and dark
    opengraph-image.tsx   share card, generated at build from content.ts
    robots.ts             sitemap.ts
  components/             Header, Sections, ThemeToggle, Reveal
  lib/content.ts          ← all site copy and data lives here
public/                   profile.jpg · Shreenivas_Joshi_Resume.pdf
archive/                  earlier versions of the site, not deployed
PRODUCT.md                audience, positioning, evidence, what must not be invented
DESIGN.md                 the design system and its rules
```

## Running it

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # production build
npm run start      # serve the production build
npm run typecheck  # tsc --noEmit
npm run lint
```

## Editing the content

**Everything a visitor reads is in [`src/lib/content.ts`](src/lib/content.ts).**
Changing a role, a figure, the tagline or a project is a one-line edit in that
file — no component contains copy. The Open Graph share card reads the same
exports, so it can never drift from the page.

Toggle the "Open to senior AI leadership roles" chip with `site.available`.

## Deploying

Push to GitHub, then Vercel → *Add New → Project → Import*. Vercel detects
Next.js; there is nothing to configure. Security headers are set in
`next.config.ts`.

### Before going live: set your domain

`site.url` in `src/lib/content.ts` is currently `https://shreenivasjoshi.com`.
It drives the canonical URL, the sitemap, `robots.txt` and every social preview,
so social cards break if it doesn't match the real host. Change that one value,
then add the domain in Vercel → *Settings → Domains*.

## How it's put together

- **Theme.** A small blocking script in `<head>` reads `localStorage`, falls
  back to `prefers-color-scheme`, and sets `.dark` on `<html>` before first
  paint, so there is no flash. `ThemeToggle` subscribes to that class with
  `useSyncExternalStore` rather than keeping its own copy of the truth.
- **Entrance animation.** The hidden start state is scoped behind a `.js` class,
  so with JavaScript disabled nothing is hidden — verified, 0 of 45 elements.
- **Colour.** One neutral ramp plus a single accent, defined once per theme in
  `globals.css` and exposed to Tailwind via `@theme inline`. No component
  hard-codes a colour. The accent is used in four places only, so it still means
  something when it appears.
- **Share card.** Generated by `next/og` at build time from the same content
  file. Satori supports a CSS subset — flexbox only, no grid.

## Adding a blog or case studies

Deferred, not designed. The app is structured so it slots in: add
`src/app/blog/[slug]/page.tsx` and a `content/` directory, most simply with
`@next/mdx`. Before writing it, read the "Not canonised" note at the end of
`DESIGN.md` — the current type scale is built for scanning, and long-form
reading needs its own.

## What's deliberately absent

`PRODUCT.md` records the things that must not be fabricated: no client names, no
employer or partner logos, no testimonials, no repository metrics, no press, no
published writing, no screenshots or diagrams from the production systems. A
GitHub section was cut from an earlier version for exactly this reason — it
described categories of work rather than actual repositories.

If any of those become real, add the real thing.
